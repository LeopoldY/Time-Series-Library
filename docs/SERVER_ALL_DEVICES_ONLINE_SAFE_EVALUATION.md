# 全设备运行时 SAFE 聚类、已训练分类模型选择与验证落地指南

日期：2026-09-15。

## 1. 任务范围与当前能力

本次目标是读取全部设备，在服务器运行时计算SAFE统计特征并聚类，按簇分配模型，然后自动选择已经训练完成的分类模型，只执行预测验证，最终按设备和历史长度汇总。

本地 `dataset/fault` 当前有80台设备，应以服务器实际扫描清单为准；不再默认设备27、58、69、83。历史长度为3、6、12、24，若有80台设备则预期320个设备/长度组合。

**本文是实施规范和服务器操作指南，不代表新入口已实现。** 现有 `run_safe_routed_batch.py` 使用固定路由CSV，读取回归 `best_backbone.pt` 并重新训练分类头，不符合本次“运行时聚类＋已训练分类头纯验证”的目标。不能靠增加设备名单或传入 `--execute` 把旧脚本变成本流程。

当前可以直接执行本文中的数据及检查点盘点命令。后文 `run_safe_online_evaluation.py` 是建议新增的入口，示例命令属于待实现的接口约定，不能在现有仓库中直接执行。

## 2. 已训练分类头必须连同配套主干加载

应递归查找 `stage2_head/best_head.pt`，不再选择 `stage1_regression/best_backbone.pt`。

当前 `best_head.pt` 实际保存：

- `stage='head'`；
- `model`：包含 `backbone.*` 与 `head.*` 的完整state_dict；
- `config`：模型结构、来源设备、历史长度、特征顺序、标签口径、阈值等；
- `validation`、`epoch`、`backbone_sha256`。

分类头训练时依赖特定主干的输出分布。即使两个主干都叫Informer，也不能把设备A的分类头与设备B的回归主干任意拼接。纯验证要加载同一份 `best_head.pt` 内的整套参数。

架构从检查点配置恢复，不用目标设备的默认路由重新覆盖模型名：构建 `SafeBinaryModel` → 严格加载完整state_dict → 调用 `freeze_backbone()` → `eval()` → 在 `torch.no_grad()` 下推理。不得调用optimizer、backward或训练入口。

## 3. 明确全设备模型覆盖策略

仅在四台设备上训练的分类模型，不会自动变成80台设备各自的专属模型。为让全部设备都能验证，建议明确采用以下策略，并在结果中标注来源：

1. 优先匹配同设备、路由模型、历史长度和特征协议兼容的完整分类检查点。
2. 没有同设备候选时，启用显式的跨设备模型复用：从允许的共享候选库中选择同一模型架构、相同长度的完整分类检查点。
3. 不允许随机初始化头，不允许更换为其他模型架构，不允许将L24模型直接用于L3，也不允许把有缺失的设备静默排除。

共享检查点即“来源于其他设备的整套已训练主干＋头”。这是跨设备泛化评估，应输出 `transfer_mode=cross_device`、来源设备及检查点路径。它不等同于给目标设备训练过专属分类器。

若不接受跨设备复用，则使用strict-device模式。缺少专属模型时必须报告缺失，不能保证320组完整覆盖。当前任务建议支持并显式启用 `same_device_then_shared`，以实现全设备验证；这种复用的效果只能通过本次评估确认。

## 4. 数据目录与一致性

默认全设备输入应为 `dataset/fault` 中的递归CSV：

```text
数据根目录/设备类别/设备编号/window_60_data*.csv
```

必须包含 `date,w_level1,w_level2,w_level3,w_level4`。设备ID取父目录，不能取CSV文件名，因为不同设备可能同名。

如果改用全设备清洗后的目录，必须先确认全部设备文件已生成，且命名和发现策略明确；`fault_selected_cleaned` 当前只覆盖四台，不能作为全设备默认输入。

同一验证批次使用一种明确的数据版本，不把四台清洗数据与其余原始数据悄悄混用。复用清洗数据上训练的检查点验证原始数据时，在报告注明输入分布及预处理差异。无论哪种输入，都不能跨时间缺口组成小时预测窗口。

输入校验：重复设备、重复或非法时间、非数值、负数、非有限计数、缺失级别列、空文件均显式报告。时间不连续可分段构造窗口，但不能简单删除时间列后按行号连续滑动。

同设备历史区间扩展或跨设备验证时，目标文件SHA256不应被要求等于源训练文件SHA256，否则无法实现新时段或新设备预测。应保留源文件哈希作为来源审计，校验特征顺序、计数尺度、时间粒度和数据协议兼容；不能直接调用旧训练续接入口的严格全文件哈希相等规则。

## 5. “运行时聚类”的时间边界

本指南将“在线”定义为：在验证开始时，用此前可用历史现场计算设备画像并分配模型；验证期间逐小时预测。并非每收到一个样本就重新跑全体KMeans。

设置统一路由截止时间T0和验证终点T1：

- 聚类特征：只用时间戳≤T0的画像数据；
- 模型或阈值选择：只能使用T0之前已知的校准数据或预先登记的共享模型选择结果；
- 正式测试标签时间：`T0 < target_time ≤ T1`；
- 每个预测输入：严格位于目标时间之前的L个连续小时。

历史画像至少50行，保持原SAFE的最小样本限制。有效设备不足3台或特征不足以形成3个不同簇时，整体给出明确诊断，不随机补簇。无历史的新设备标记cold_start，不能利用其测试期数据计算画像。

不应对全量文件先聚类再声称是在线验证，也不能用每台文件各自的70%切分忽略不同设备的实际时间边界。

**检查点时间边界也必须审计。** 被选模型的训练和早停验证数据不得超过T0；否则模型已经使用了未来信息。当前检查点配置没有完整的训练时间清单，需要由源数据及其切分规则追溯，并生成 `training_end`、`selection_end` 字段。跨设备候选同样需要检查，尤其源设备也包含在测试集合内时。不能仅凭文件名或创建时间推断训练截止时间。

若现有模型训练/早停时段与计划测试时段重叠，应调整T0至所有候选允许的时间之后，或使用更早的检查点；若无法确认边界，只能标为回顾性验证，不能声称无未来信息。

## 6. 运行时 SAFE 聚类与路由

每台设备、每个级别分别计算：

- Sparsity：该级别计数为0的比例；
- Mean：平均计数；
- CV：总体标准差/均值，均值≤1e-6时取0。

共12维。只在T0之前的设备画像上拟合StandardScaler，再执行 `KMeans(n_clusters=3, random_state=42, n_init=10)`。设备按数字编号排序，记录软件版本。

每个设备的路由稀疏度取四级零值比例的平均；各簇再求该值的均值，由低到高命名：

| 类别 | 模型 |
| --- | --- |
| Dense | Informer |
| Intermittent | iTransformer |
| Sparse | PatchTST |

这是此前四级SAFE适配采用的口径。簇名是相对分组，不是单设备绝对故障频度。四级零值比例的平均不等于四级同时无告警的窗口比例。

保存12维特征、标准化器参数、簇中心、类别映射、T0和设备清单。测试期间固定路由，不在测试数据上重新拟合。如果后续需要滚动重聚类，应定义独立的路由版本和生效时间，任何版本只使用当时之前的数据。

## 7. 自动选择已训练分类模型

构建分类模型登记表，至少包含：

```text
checkpoint_path, checkpoint_sha256, source_device_id, model, seq_len,
head_hidden, head_dropout, d_model, n_heads, d_ff,
feature_order, label_rule, data_protocol, threshold,
training_end, selection_end, selection_metric, selection_score,
backbone_sha256, source_data_sha256, shared_allowed
```

选择过程：

1. 过滤损坏或非head检查点，检查模型和历史长度覆盖。
2. 按第3节限定同设备或共享候选。
3. 排除时间边界超限、标签不符、特征协议不符的候选。
4. 同设备同口径候选可按其合法验证指标选择。跨设备模型不得直接比较各来源设备的加权BCE：类别权重、正例率及验证分布不同。
5. 若需自动比较共享候选，使用目标设备T0之前的同一校准时间段，对所有候选作纯推理评分。优先用AP；同分时使用预定稳定规则。校准标签不进入梯度更新，不使用正式测试标签。
6. 校准段没有正类或没有足够样本时，不伪造AP排名：使用事先在独立公共校准集上登记的候选顺序，或明确标记无法选择。没有这个预登记顺序就停止对应任务。
7. 阈值默认保留所选检查点的配置值，不根据本次测试结果调整。若需要重新校准阈值，另行记录校准范围和选择规则。

如当前没有校准时间段或候选登记信息，第一版可以每个模型/长度预先指定一个共享检查点，再让程序自动按路由检索它；这属于固定登记选择，不应包装成目标设备上的自动择优。

## 8. 全覆盖检查与纯推理

在推理前生成任务矩阵：设备×历史长度×路由模型×分类检查点。若80台设备、4个长度，预期320组。

默认严格覆盖模式：任一任务缺少模型、有效时间窗或来源审计，则输出全部缺失原因并非零退出。可提供显式allow-partial用于诊断，但结果必须标为partial，不能显示complete。

每组使用相同正式测试时间边界；窗口断点与历史长度可能导致有效目标时间不同，应输出实际样本数和起止时间。需要严格跨长度比较时，额外在各长度共同目标时间交集上报告指标，同时保留原始全窗口指标。

推理过程：

```text
历史L小时四级计数
→ 已训练、冻结、eval模式的主干
→ 同检查点内的已训练分类头
→ Sigmoid分数
→ 已冻结阈值
→ 下一小时故障判断
```

标签 `any(w_level1..w_level4 at target_time > 0)` 仅用于计算评估指标；未来计数不能输入模型。已知未来日历时间特征可以使用。

## 9. 需要新增的代码模块

| 模块 | 职责 |

| `run_safe_online_evaluation.py` | 全设备发现、时间协议、任务覆盖、纯验证调度及汇总 |

## 11. 新入口实施后应提供的操作接口（当前不可直接执行）

下面的参数是待实现接口约定，T0/T1及校准起点必须根据服务器实际训练时间和数据覆盖确定，不能照抄占位符。

## 12. 输出及完成标准

```text
outputs/safe_all_devices_evaluation/批次时间戳/
├── protocol.json
├── data_inventory.csv
├── checkpoint_registry.csv
├── device_features.csv
├── clustering.json
├── routing.csv
├── plan.json
├── coverage.csv
├── completion.json
├── predictions/设备/历史长度/predictions.csv
├── all_metrics.csv
├── by_length.csv
├── common_time_metrics.csv
└── REPORT.md
```

预测文件除原字段外，增加 `source_device_id`、`transfer_mode`、`checkpoint_sha256`、`routing_version`、`evaluation_protocol`，区分专属设备验证与跨设备泛化。

每设备每长度报告Accuracy、Precision、Recall、F1、AP、ROC-AUC、FPR、TN/FP/FN/TP、正负样本数、正例比例及始终正常基线。AP用average precision；无正例时Recall/F1/AP为N/A，单类时ROC-AUC为N/A。

按长度分别报告设备宏平均和混淆矩阵微平均，宏平均同时给有效设备数；不把不同长度重复的时间窗口拼成一个总分。不同模型分数未必可比，不将跨设备概率池化的AP/AUC当作默认整体指标。

完成条件：实际发现设备数、预期任务数、成功数和失败数均可审计；所有预期任务成功才写complete=true。若任何设备无法验证，应逐项列出原因。

## 13. 上线前验证清单

- 扫描器无四设备白名单，新增设备会进入任务矩阵。
- 修改T0之后的数据不会改变路由；测试标签不参与候选及阈值选择。
- 跨设备模型复用明确标记，完整主干与头来自同一检查点。
- 全模型/长度覆盖缺失会阻止“完整”执行。
- 历史与目标严格相隔一小时，窗口不跨断点。
- 纯验证前后全部模型参数及buffer的校验值一致，未调用优化器或反向传播。
- 指标从预测文件重算，并与独立混淆矩阵核对。
- 对零正例、重复文件、候选缺失、损坏检查点、冷启动设备都有明确结果。

本阶段先完成上述新增入口，再在服务器试跑少量设备检查模型来源与预测输出，最后执行全设备批次。仅依靠现有四设备脚本，无法满足本次全设备运行时SAFE路由和已训练分类模型纯验证要求。
