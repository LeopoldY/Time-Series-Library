# SAFE 下一时间步故障二分类适配建议

日期：2026-09-14。本文基于本地入口、模型、数据加载和训练代码，以及四台设备 CSV 的只读核查；本次仅新增本文档，不修改算法代码、不转换数据、不启动训练。

## 1. 建议结论与范围

建议保留 SAFE 的“设备统计特征 → KMeans 聚类 → 模型路由 → 历史滑窗 → 单步预测”流程，在现有模型单步输出后包装一个 `Linear(1, 1)` 二分类头。训练目标改为二元交叉熵，推理输出故障概率及 0/1 判断。新增头仅有两个可训练参数，Informer、PatchTST、iTransformer 的内部结构及预测前向路径均可保留。

这需要配套调整标签、损失和评估接口；仅在回归输出后加 Sigmoid、继续使用原来的 MSE 和计数标签，不能完成所需的分类训练。建议采用一个默认关闭的 `fault_binary` 开关，在现有 `long_term_forecast` 路径中启用适配，以保留原预测调用约定。

本轮范围仅为设备27、58、69、83，每台设备独立生成滑窗和训练，沿用历史长度 `3、6、12、24`，`pred_len=1`、`label_len=1`。不合并设备时间序列，不增加新骨干模型或重新设计路由。

现有映射保持为：Dense → Informer，Intermittent → iTransformer，Sparse → PatchTST。只使用四台设备重算三簇，路由可能与此前全设备聚类不同，这是输入集合变化的结果；不应事先硬编码各设备模型。四个样本聚三簇的稳定性有限，需保存实际聚类特征、中心和映射。

仓库另有 `SAFE_classification.py`，但它使用 UEA 数据、阈值路由及 TimesNet，且采用 `pred_len=0`。它不等价于本入口的最小适配，不建议直接替换。现有 `task_name=classification` 还会进入专用数据整理和模型分类分支，例如 Informer 将绕开原预测解码路径，因此不建议仅改任务名称。

## 3. 标签定义：必须显式记录的业务假设

为最小程度延续当前 `target=w_level4`，建议首版默认采用：

`y[t+1] = 1{w_level4[t+1] > 0}`。

这严格表示“下一小时是否出现四级告警”，是当前故障目标的代理标签，不等同于任意告警、实际设备失效或故障持续状态。当前 CSV 不包含独立的故障真值字段，不能验证告警与真实故障的一一对应关系。

如果“有故障”在业务上指任一级别告警出现，则改用 `1{sum(w_level1…w_level4)[t+1] > 0}`，并在实验元数据中使用不同的 `label_rule`。这会改变任务含义，不能为了增加正例而静默替换。该口径可复用同一包装头，但需从下一步四列原始计数构造标签；聚类仍可沿用 `w_level4`，以保持原路由流程。

## 4. 最小分类头设计

推荐数据流：

```text
历史四级计数 X[t-L+1:t]，形状 [B,L,4]
  → 原模型预测前向（包括原归一化、投影及反归一化）
  → 取最后一步、w_level4 对应输出，形状 [B,1,1]
  → Linear(1,1)，得到 logits，形状 [B,1,1]
  → 训练：BCEWithLogitsLoss(logits, y[t+1])
  → 推理：sigmoid(logits)，按阈值输出 0/1
```

Informer 在当前 `c_out=1` 下输出一个通道；PatchTST 和 iTransformer 的预测输出仍可能包含四个变量，应按数据加载器将 `w_level4` 置于末列的规则显式切片。不能假定三个模型均会因 `c_out=1` 自动返回一个通道。

建议新建共享 `nn.Module` 包装器，包含原模型与分类头，在 `_build_model` 内、DataParallel 包装之前构造。分类头因此自动进入优化器、设备迁移、训练/评估模式和检查点保存。包装器返回与现有预测循环兼容的 `[B,1,1]` logits。

首版采用骨干与头联合训练，仅以 BCE 优化；“不改算法流程”指保留结构和计算路径，不表示冻结权重。原单步输出在联合训练后成为分类用的中间标量，不再承诺具有故障次数预测含义。若只冻结回归模型训练两个参数，本质上主要是校准原输出，表达能力更受限制，不建议作为默认训练方式。

该方案有意保留单标量瓶颈，以满足最小改动约束。如果后续效果不足，再另行评估对隐藏表示池化后接线性头；那需要分别接入三种模型内部，超出本轮建议范围。不要先对回归结果做 `>0` 硬阈值再训练分类头，该操作不可导。

## 5. 数据对齐及训练约定

1. 输入仍为历史四列计数。索引从 0 开始时，样本 `X[i:i+L]` 的标签取原始行 `i+L`，不能使用输入最后一行 `i+L-1` 作为标签，也不能对历史窗口做“曾发生故障”聚合来替代未来标签。
2. 保留现有解码器输入：历史 `label_len` 行加未来一步零占位。必须先用原计数构造解码器输入，再单独生成损失标签；未来真实计数与标签均不能喂入模型。下一步时间特征可用，因为时间本身预先可知。
3. 最小版显式保持 `scale=False`，直接从原始计数生成 0/1 float 标签。若以后启用标准化，需另行保留未标准化标签；不能对标准化计数直接判断 `>0`。概率和 logits 不做回归反标准化。
4. 沿用按时间约 70%/10%/20% 的切分。验证和测试可借用前一时间段的历史上下文，但标签索引必须分别位于各自时间段内。每个设备、每个 L 的训练窗口数为 `7142-L`，验证 1022，测试 2040，前提为保留现有跨边界上下文逻辑。
5. 聚类特征和聚类用 StandardScaler 仅由四台设备训练段拟合，避免测试数据影响模型选择。仍使用原 KMeans 算法与映射规则；不足三个有效设备或无法产生三种有效簇时给出清晰诊断，不能静默引入新路由。
6. 使用 `BCEWithLogitsLoss`，训练不提前 Sigmoid。可采用 `pos_weight=N_negative/N_positive`，仅按当前设备、当前 L 的训练标签计算；极稀少正例可能产生很大权重，记录具体值和训练稳定性。若训练窗口无正例，停止该设备训练并说明原因，不能除零。
7. 默认阈值 0.5，若调阈值只用验证集，选择后冻结。使用类别加权时，Sigmoid 数值未必是校准后的实际故障概率；需将阈值、权重与模型一起保存。验证集仅两个正例的设备不宜依赖精细阈值搜索。
8. 沿用 Adam、学习率及早停机制，早停监控验证 BCE；损失按样本数加权汇总，避免末尾小批次影响。现有训练每轮还计算测试损失，建议分类模式关闭该操作，最终模型和阈值确定后再评估测试集。
9. 首版关闭数据增强，避免计数与标签对齐变化；训练窗口可打乱批次，但不能打乱原始序列后重新切分。验证与测试保持时间顺序，便于逐时刻导出结果。

## 7. 评估与验收

主要报告每台设备的 Precision、Recall、F1、PR-AUC（明确采用 average precision 口径）、混淆矩阵及正负样本数，辅助报告 ROC-AUC、Accuracy。保留逐设备指标，设备宏平均应标明有效设备数，不让设备83掩盖其他设备的稀少正例问题。

对无正例测试段，Recall、正类 F1、AP 和 ROC-AUC 标注为 N/A 并说明原因，不将库函数的默认返回值当成有效性能证据；仍可报告误报数、假阳性率和混淆矩阵。对于存在正例但没有预测正例的情况，约定 Precision 为 0 并注明、F1 为 0。不要只以 Accuracy 判断效果。

增加两种无需训练的比较：始终预测无故障，以及用当前小时的标签预测下一小时。逐时刻导出 `device_id,target_time,y_true,probability,y_pred,threshold,model,seq_len,label_rule`。

实施后的必要验收：

- 四台设备各且仅加载一次；原始 CSV 不变，所有实验输出相互隔离。
- 用小型人工序列核对每个窗口标签恰为下一行；未来标签不进入输入或解码器。
- 三个骨干各进行一个前向与反向批次，确认 logits/标签均为 `[B,1,1]`、梯度有限且分类头参与更新。
- 覆盖 CPU 或实际可用设备；如启用 AMP，另查对应分支标签和损失一致性。
- 保存并重载检查点，在 eval 模式下对同一批输入得到一致输出。
- 核查时间切分、训练窗口正例数、仅训练段拟合聚类，以及无正例指标处理。
- 关闭分类开关时，回归模型构造、MSE 和输出契约保持原行为。

本文不包含训练结果或性能提升承诺。下一阶段可据此实施；需在实验配置中明确采用“四级告警”还是“任一级别告警”作为故障代理标签，不能将两者结果混用。
